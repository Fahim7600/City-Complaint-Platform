# Render Deployment Guide

This guide details the manual setup of the City-Complaint-Platform backend service on Render.

---

## 1. Create Web Service in Render

1. Log in to your [Render Dashboard](https://dashboard.render.com).
2. Click **New +** and select **Web Service**.
3. Connect your GitHub repository (`City-Complaint-Platform`).
4. Configure the runtime settings:
   - **Environment:** `Node`
   - **Build Command:** `npm run render:build`
   - **Start Command:** `npm start`
   - **Health Check Path:** `/api/v1/health`

---

## 2. Environment Variables

Add the following environment variables in the Render dashboard (Settings -> Environment). Do not put secret values in repository files.

- `NODE_VERSION` (set to `24`)
- `PORT` (e.g., `3000` or leave Render default)
- `DATABASE_URL`
- `NODE_ENV` (set to `production`)
- `ALLOWED_ORIGINS`
- `ADMIN_SEED_EMAIL`
- `ADMIN_SEED_PASSWORD`
- `DEMO_USERS_PASSWORD`
- `JWT_ACCESS_SECRET` (at least 32 characters, distinct from refresh secret)
- `JWT_REFRESH_SECRET` (at least 32 characters, distinct from access secret)
- `JWT_ACCESS_EXPIRY` (e.g., `15m`)
- `JWT_REFRESH_EXPIRY` (e.g., `7d`)
- `GOOGLE_CLIENT_ID`
- `CLOUDINARY_CLOUD_NAME`
- `CLOUDINARY_API_KEY`
- `CLOUDINARY_API_SECRET`
- `STRIPE_SECRET_KEY`
- `STRIPE_WEBHOOK_SECRET` (see Stripe setup below)
- `STRIPE_PREMIUM_PRICE_ID`
- `APP_BASE_URL` (set to `https://<your-render-service>.onrender.com`)
- `FRONTEND_BASE_URL` (optional, set once frontend is hosted)

---

## 3. Stripe Webhook Configuration

1. **Initial Deploy with Placeholder:**
   - On the first deployment, set `STRIPE_WEBHOOK_SECRET` to a temporary placeholder value such as `whsec_placeholder`.
   - Deploy the service to obtain your public Render URL (`https://<render-url>.onrender.com`).

2. **Create Stripe Webhook Endpoint:**
   - In the [Stripe Dashboard](https://dashboard.stripe.com/webhooks), navigate to **Developers -> Webhooks**.
   - Click **Add endpoint** with the URL:
     ```
     https://<render-url>.onrender.com/api/v1/payments/webhook
     ```
   - Select the following events to listen for:
     - `checkout.session.completed`
     - `customer.subscription.updated`
     - `customer.subscription.deleted`
     - `invoice.payment_succeeded`
     - `invoice.payment_failed`

3. **Update Webhook Secret & Redeploy:**
   - Copy the Signing Secret (`whsec_...`) generated by Stripe.
   - Update `STRIPE_WEBHOOK_SECRET` in your Render Environment settings with this value.
   - Trigger a redeploy in Render so the backend uses the verified signing secret.

> **Important Note:** Local `stripe listen` and the Render deployed webhook point to the same database. Ensure only one listener is active when testing payments to prevent duplicate event handling.

---

## 4. Frontend Integration (Next.js)

When the frontend is deployed to a separate domain:
- Set `FRONTEND_BASE_URL` to the frontend URL (e.g., `https://my-frontend.vercel.app`).
- Add the frontend origin to `ALLOWED_ORIGINS`.
- In `production` mode, the refresh token cookie is automatically configured with `SameSite=None` and `Secure=true`, enabling cross-site authentication between the distinct frontend and backend origins.
